
ソフトウェアフレームワーク機能の「トランザクション」機能は、DynamoDB、RDB、SQSおよびS3を対象に処理する。
業務処理中に、DynamoDBのトランザクション項目、SQS送信メッセージおよびS3補償対象をトランザクションコンテキストに蓄積する。
業務処理が正常終了した場合、DynamoDBのトランザクション書込み、RDBトランザクションのコミット、SQSメッセージ送信の順に処理する。
業務処理が異常終了した場合、またはDynamoDBもしくはRDBのコミット処理でエラーが発生した場合、RDBトランザクションのロールバック、DynamoDB補償トランザクションおよびS3補償トランザクションを実行する。
S3補償トランザクションでは、補償トランザクション用の関数でアップロード時に登録したS3オブジェクトを、バージョンIDを指定して削除する。
DynamoDB補償トランザクションでは、トランザクション内で作成したレコードを削除する。更新または削除したレコードの復元は行わない。
SQS送信に失敗した場合は、エラーをログ出力する。SQS送信処理のエラーは呼出元へ返却せず、DynamoDB、RDBおよびS3の補償処理は実行しない。
コンシューマ側でメッセージステータスをcompleteに更新する。メッセージステータス更新処理がエラーを返却した場合は、エラーをログ出力する。メッセージステータス更新処理のエラーは呼出元へ返却せず、補償トランザクションは実行しない。
SQSメッセージの正常送信後は、実際のSQSメッセージID、TTLおよびprocessingステータスをSQSメッセージIDテーブルへ登録しない。
#### 2.3.1. プロデューサのシーケンス

プロデューサのシーケンス図を以下に示す。

![sqs prd sequence](images/sqs_prd_sequence.png)

| 項番 | 操作 | 説明 |
|----|----|----|
| （1） | トランザクション追加（DB） | DynamoDBへ登録、更新または削除するデータをトランザクションコンテキストに蓄積する。CreateOneWithTransaction および CreateLargeOneWithTransaction で登録するデータについては、補償用の削除トランザクションアイテムも蓄積する。DynamoDBのトランザクション項目数は、DynamoDBへ登録、更新または削除するデータ数で計算する。SQS送信メッセージおよびSQSメッセージIDテーブルのメッセージステータスは、DynamoDBのTransactWriteItemsの項目数には含まれない。 |
| （2） | トランザクション追加（SQS） | SQSのキューに送信するメッセージをトランザクションコンテキストに蓄積する。DynamoDBのトランザクション項目数は、DynamoDBへ登録、更新または削除するデータ数で計算する。SQS送信メッセージおよびSQSメッセージIDテーブルのメッセージステータスは、DynamoDBのTransactWriteItemsの項目数には含まれない。 |
| （3） | データ登録（S3） | S3にデータを登録し、登録したオブジェクトのバケット名、キーおよびバージョンIDを補償トランザクションアイテムとして蓄積する。 |
| （4） | データ登録（DynamoDB SDK） | 業務処理が正常終了した場合、トランザクションコンテキストに蓄積したDynamoDBトランザクションアイテムを TransactWriteItems で登録する。 |
| （5） | コミット（RDB） | RDBトランザクションを使用する場合、DynamoDBのトランザクション書込み成功後にRDBトランザクションをコミットする。 |
| （6） | メッセージ送信（SQS SDK） | DynamoDBおよびRDBのコミット成功後、トランザクションコンテキストに蓄積したメッセージをSQSへ送信する。標準キューではAppConfigに設定された遅延時間を設定する。FIFOキューでは個別メッセージの遅延時間を設定しない。 |
| （7） | 送信エラー情報登録 | SQS送信に失敗した場合、insert_error_<UUID> をメッセージIDとして生成し、キュー名、メッセージグループIDおよびメッセージ本文をSQSメッセージIDテーブルへ通常登録する。 |
| （8） | 補償処理 | 業務処理が異常終了した場合、またはDynamoDBもしくはRDBのコミットに失敗した場合、RDBトランザクションをロールバックし、DynamoDB補償トランザクションを実行し、S3に登録した補償対象オブジェクトをバージョンID指定で削除する。 |
| （9） | SQS送信・ステータス更新エラー処理 | SQS送信またはコンシューマのメッセージステータス更新に失敗した場合、エラーをログ出力する。これらのエラーは呼出元へ返却せず、DynamoDB、RDBおよびS3の補償処理も実行しない。 |

SQSメッセージ送信後は、送信結果のメッセージID、TTLおよびprocessingステータスをSQSメッセージIDテーブルまたはDynamoDBトランザクションへ登録しない。

※1：遅延時間のAppConfig設定イメージを以下に示す。

| No | キー（論理名） | キー（物理名） | 概要 | デフォルト値 |
|----|----|----|----|----|
| 1 | メッセージ遅延時間 | Y00_SQSCONFIG_DELAYSECONDS | メッセージの配信遅延時間。 | 3 |

#### 2.3.2. コンシューマのシーケンス

コンシューマのシーケンス図を以下に示す。

![sqs cs sequence](images/sqs_cs_sequence.png)

| 項番 | 操作 | 説明 |
|----|----|----|
| （1） | メッセージ受信 | SQSを監視するLambdaから実行される。 |
| （2） | メッセージID取得 | プロデューサ側でSQSメッセージIDテーブルに登録されたメッセージIDを取得する。 |
| （3） | エラー処理 | 以下の場合に発生する。<br>・ （2）でメッセージIDを取得できなかった場合。※1<br>・ （2）で取得したメッセージIDと紐づくメッセージのメッセージステータスが完了の場合。※2<br>・ （2）で取得したメッセージIDと紐づくメッセージのメッセージステータスがロールバックの場合。※3 |
| （4） | 業務処理呼出 | 業務処理を呼び出す。 |
| （5） | トランザクションアイテム追加（SQS） | SQSのキューに送信するメッセージをトランザクションコンテキストに蓄積する。SQS送信メッセージはDynamoDBのTransactWriteItemsには含まれない。 |
| （6） | トランザクションアイテム追加（DB） | DynamoDBの更新または登録を行うデータをトランザクションコンテキストに蓄積する。DynamoDBのトランザクション項目数は、TransactWriteItemsの最大100件および合計4MBの制約を考慮する。 |
| （7） | データ登録（S3） | S3にデータを登録し、登録したデータを補償トランザクションアイテムに蓄積する。 |
| （8） | DynamoDBトランザクション処理 | 業務処理が正常終了した場合、業務処理中にトランザクションコンテキストへ追加したDynamoDBトランザクションアイテムを TransactWriteItems で登録する。 |
| （9） | RDBトランザクションコミット | RDBトランザクションを使用する場合、DynamoDBのトランザクション書込み成功後にRDBトランザクションをコミットする。 |
| （10） | メッセージ送信（SQS SDK） | 後続メッセージがトランザクションコンテキストへ追加されている場合、DynamoDBおよびRDBのコミット成功後にSQSへ送信する。 |
| （11） | メッセージステータス更新	 | コンテキストにSQSメッセージIDテーブルの情報が設定されている場合、メッセージステータスを complete に更新する。この更新はDynamoDBトランザクションには含まれず、通常の更新処理として実行する。 |
| （12） | 補償処理 | 業務処理が異常終了した場合、またはDynamoDBもしくはRDBのコミットに失敗した場合、RDBロールバック、DynamoDB補償トランザクションおよびS3補償トランザクションを実行する。 |

※1：メッセージIDが取得できなかった場合、エラーと見なすが、メッセージが複数件受信されることを考慮し、後続のメッセージの処理を継続する。\
※2：メッセージが処理されていた場合は成功として返すため正常終了する。\
※3：メッセージステータスがロールバックの場合、プロデューサ側でDynamoDBのトランザクションに失敗しているため、メッセージの処理ができない状態であることから、正常終了として返しメッセージを破棄する。
